# Подход к тестированию

## Цель

Проверить POST-метод создания организации по документации: авторизацию, позитивные сценарии, валидацию полей и обработку тела запроса.

## Покрытие

| Папка | Запросов | Проверки |
|---|---:|---|
| Авторизация | 3 | Получение токена, запросы без токена и с невалидным токеном |
| Позитивные сценарии | 6 | Ветки алгоритма для ИНН из 10 и 12 цифр, с ОГРН и без него |
| Валидация name | 5 | Отсутствие поля, длина |
| Валидация inn | 8 | Отсутствие, длина, формат, повторная регистрация |
| Валидация ogrn | 6 | Обязательность, длина, формат, поведение при ИНН из 12 цифр |
| Валидация address | 5 | Отсутствие поля, длина |
| Валидация phone | 5 | Форматы и длина |
| Валидация head | 17 | Массив руководителей, границы длины имени, фамилии и отчества |
| Валидация тела запроса | 4 | Пустой объект, отсутствие тела, невалидный JSON, лишние поля |

**Итого: 59 запросов в 9 папках.**

## Техники

- Граничные значения для полей с ограничениями длины.
- Позитивные сценарии для основных веток алгоритма.
- Негативные проверки обязательности, формата и длины полей.
- Проверки тела запроса и авторизации.

## Ограничения

- Часть сценариев зависит от предыдущих запросов, например повторная регистрация.
- Не проверялись несоответствия типов данных, пустые строки отдельно от отсутствующих полей и массив руководителей с одним невалидным элементом.
