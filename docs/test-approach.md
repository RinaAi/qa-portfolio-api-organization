# Подход к тестированию

## Цель

Проверить REST API метод создания организации (`POST /api/v1/de/organization`) на соответствие документации: схема запроса, таблица валидации, алгоритм обработки.

## Область

**Входит:**
- Авторизация (Bearer token)
- Позитивные сценарии (happy path)
- Обязательность полей
- Граничные значения длины
- Форматы (ИНН, ОГРН, телефон)
- Бизнес-логика: зависимость ОГРН от длины ИНН, уникальность ИНН

**Не входит:**
- Нагрузочное тестирование
- UI
- Другие методы API (кроме вспомогательных проверок)

## Техники тест-дизайна

1. **Классы эквивалентности**  
   Валидные и невалидные наборы для каждого поля.

2. **Граничные значения**  
   Для строковых полей и числовых идентификаторов: min−1, min, max, max+1.

3. **Негативное тестирование**  
   Отсутствие обязательных полей, пустые значения, неверный формат, повтор ИНН.

4. **Проверка статусов и сообщений**  
   Ожидаемые коды: 200 (успех), 400 (валидация), 401 (авторизация).

## Порядок работы

1. Изучение документации (схема + таблица валидации + алгоритм)
2. Составление списка проверок по полям и правилам
3. Сбор Postman-коллекции с понятной структурой папок
4. Прогон позитивных и негативных кейсов
5. Фиксация расхождений документации и фактического поведения
