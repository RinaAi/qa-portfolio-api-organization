# Найденные особенности и расхождения

## 1. Бизнес-логика ИНН и ОГРН

**По алгоритму:**
- ИНН из 10 цифр → ОГРН обязателен
- ИНН из 12 цифр → ОГРН не обязателен

При тестировании часть сценариев вела себя иначе, чем описано в таблице валидации. Расхождение зафиксировано; для проверки фактического состояния использовались дополнительные запросы.

## 2. Невалидный токен авторизации

При отсутствии токена — ожидаемо **401**.  
При невалидном токене в части случаев возвращался **500** вместо 401.  
Зафиксировано как несоответствие ожидаемому поведению API.

## 3. Уникальность ИНН

Повторная отправка запроса на создание организации с уже существующим ИНН возвращает **400** с сообщением о том, что организация уже зарегистрирована.  
Поведение соответствует бизнес-правилу уникальности.

## 4. Обязательность и пустые значения

Обязательные поля (`name`, `inn`, `address`, блок `head` и др.) при отсутствии или пустом значении дают **400** с описанием ошибки валидации.

---

Эти наблюдения показывают разницу между «тестом по документации» и проверкой реального поведения API — важный навык при работе с неполными или устаревшими требованиями.
